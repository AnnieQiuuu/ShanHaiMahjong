# 山海麻将产品方向与实施路线

## 设计依据

用户已指定项目根目录的《山海麻将_GDD_v2_60宠物详细版.docx》为完整游戏的最终宗旨。本文记录其产品目标、当前差距与实施顺序；具体设计以原文为依据，后续明确的用户决定优先。文档中的建议数值仍属于待验证的平衡参数。

## 完整游戏目标

宠物主题上海麻将，线性推进八地区、共40关，通过亲手配对发现并收集60只山海灵兽。五元素各12只，每只只属于一个玩法元素。单关种类逐步增加，常规上限16种。

- 基础操作：相同宠物两张配对；上方牌面无遮挡，同层同排左右至少一侧开放；允许跨层配对。
- 五行：手动配对后自动触发火、雷、风、水、土效果，无需再次选择目标。
- Combo：连续手动消除同元素累积，无时间限制；换元素从×1开始。自动效果不增加也不打断，洗牌清零，撤回恢复。
- 收藏：开局已有五元素各一只基础宠物；新宠物只有首次手动配对才算发现，立即存档，失败保留。自动效果须保护未发现宠物。
- 容错：死局检测、有限撤回、保持几何不变的剩余牌重排；无洗牌资源且死局时失败，可以重开。
- 美术：保留已批准手绘牌体与原始宠物PNG；牌上宠物为视觉主体，美术参数可在编辑器调整。
- 范围：图鉴、线性关卡与五行反馈；暂不加入抽卡、养成、装备、货币经济、排行榜或Boss战。

## 当前基础与差距

更新：本节以下为最初评估记录；现已按用户后续决定实现八地区各一关、单张五行与奇数残牌洗牌。当前行为见MVP_FIVE_ELEMENTS.md，后续决定优先于下述历史建议。

现有代码包含36张三层牌阵、14个宠物图片ID中抽9种、每种4张、初始可解生成、配对、胜利、死局提示、撤回及提示。尚无完整洗牌、有限次数、失败流程、五行、Combo、关卡推进、发现存档或图鉴。

当前AGENTS.md要求固定36张（24+8+4）、9种各4张；完整GDD要求24至约100张、不同层数与4至16种。实施关卡系统时需要同步更新约束和测试，并保留36张原型作为回归场景。本文不直接改变现有约束或运行行为。

现有14个图片ID不足以确认全部60只的名称、元素、基础宠物及地区归属。后续应建立用户确认的美术映射，不按文件序号猜测，不生成或覆盖缺失美术。

## 小步实施与验收

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| P0 核心闭环 | 洗牌、撤回与洗牌次数、死局及失败、重开 | 洗牌保留剩余数量、宠物数量和几何，至少产生合法对子；耗尽后失败；保留R/Z/H |
| P1 五行基础 | 五元素×1、自动目标、新宠物保护 | 效果合法、无二次点选、不会抢走新发现；每次玩家操作及其自动效果可整体撤回 |
| P2 Combo | 同元素连续计数、×1至×5效果、完整回退 | 思考不会断连；自动效果不改计数；撤回恢复Combo及护佑等局内状态；洗牌清零 |
| P3 内容管线 | 宠物、布局、关卡数据配置 | 牌数、层数、宠物池、次数来自配置；不修改核心代码即可添加关卡；保留初始可解验证 |
| P4 收藏与进度 | 选关、发现提示、存档、60格图鉴 | 手动发现立即保存且失败保留；局内撤回不抹除已保存发现；解锁与重新进入正确 |
| P5 关卡内容 | 八地区各五关 | 控制单关辨识负担，验证各关可解性与连续难度，记录死局及辅助功能使用情况 |
| P6 表现与QA | 背景、基础音效、五行动画、触屏和交互 | 原画保持完整、操作反馈清楚，完成真实窗口与目标设备验证 |

每批代码改动检查模块边界，并在Godot可用时运行headless解析、主场景与相关测试；视觉和操作手感另行验证，不把无画面测试当作美术验收。

## 实施前需细化的机制

火与风可能单张移除，水的“解放”也未指定确切状态变化。需要定义如何处理剩余宠物奇数、残留单张、保护目标及无目标情况，确保辅助效果不会制造无法清空的残局。水应采用可测试且区别于火、风的规则，再进入正式实现。

撤回的局内快照须覆盖手动对子、附加效果、Combo、护佑及相关状态。永久发现记录与局内快照分离。数值与目标优先级依据GDD起步，通过实际牌局验证后调整。
